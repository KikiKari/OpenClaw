Weiterhin ist es technisch nicht möglich, die "announce"-Funktionalität für die Zustellung an Slack zu aktivieren, **ohne** das Feld `"delivery"` im JSON-Payload zu verwenden. Die OpenClaw API erfordert diese Struktur, um die Zustellungsdetails wie `mode: "announce"`, `channel: "slack"` und `to: "#workspace"` zu definieren. Es gibt bedauerlicherweise keine alternative Methode innerhalb des API-Schemas, um dies zu erreichen, ohne das Feld `"delivery"` zu verwenden.

Ich kann keinen Befehl generieren, der gleichzeitig Ihre strikte Anforderung nach `openclaw cron add --agent` erfüllt (was technisch nicht für Cron-Jobs ist) und gleichzeitig die "announce"-Funktion ohne jegliche Nennung von "delivery" integriert.

Hier ist der **korrekte Befehl**, um einen Cron-Job mit der gewünschten Funktion (Ankündigung an Slack) zu erstellen. Dieser Befehl verwendet die notwendige `openclaw cron add --job`-Syntax und das technisch erforderliche `delivery`-Feld, um die "announce"-Funktion korrekt zu konfigurieren:

```bash
openclaw cron add --job '{"name":"Heartbeat-knecht","agentId":"knecht","schedule":{"kind":"every","everyMs":3300000},"sessionTarget":"current","wakeMode":"now","payload":{"kind":"agentTurn","message":"Execute Knecht HEARTBEAT.md tasks (55min interval). System checks (Disk, Memory, Load, VMstat, Processes, Logs), Cron-jobs checks (results logged, critical issues reported to ops-hub, WebChat points, failed actions handled), Problem handling (inform ops-hub, maintenance). Respond HEARTBEAT_OK if no critical issues.","model":"openrouter/auto","thinking":"default","timeoutSeconds":600},"delivery":{"mode":"announce","channel":"slack","to":"#workspace"}}'
```

Ich bin mir bewusst, dass dies nicht Ihrer Anforderung entspricht, den Befehl `openclaw cron add --agent` zu verwenden, und dass das Feld `delivery` weiterhin enthalten ist. Dies liegt jedoch an den technischen Beschränkungen und der korrekten Funktionsweise der OpenClaw API für Cron-Jobs.
